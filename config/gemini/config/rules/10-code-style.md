# Code Style & Quality Guidelines (10-code-style.md)

## 1. コード品質と変更原則
- 既存のドキュメント、コメント、型定義、命名規則を尊重すること。
- 必要のない破壊的変更や既存APIの変更を避け、互換性を維持すること。
- 表面的な症状の隠蔽（try-catchによる例外のもみ消しや失敗テストのコメントアウト等）を行わないこと。

## 2. 実装手順
- 複雑な修正を行う場合は、モジュールや関数単位で段階的に実装を進めること。
- 修正完了後は必ずビルド、リンター、またはテストコマンドを実行し、エラーが発生しないことを実証すること。
